Srv\_TrnOffDly

The turn off delay debounces the true to false transition.  
This means that if the input is true, the output is set to true immediately. If the input has been false at least for the delay time, the output is false.

| Hint |
| --- |
| fter the initialization of the RAM (e.g. power on reset), the static element which holds the timer is zero. Thus, the output of the element is true until the delay time has elapsed, despite the input never has been set to true. To avoid this, the static element has to be initialized with MAXSINT32.  This class does not contain sequence numbers for the class methods.  The out value has to be connected to a variable to compute the class.  if the output is used in multiple places, there is a risk that the class output might be calculated twice. To avoid this use a process local variable at the output of the class(incase output is used in multiple places). |

| Attention |
| --- |
| Each function call of the method 'out' calculates a new value for the internal time value of the delay element. Thus, it is highly recommended to ensure that the element gets calculated once in each process step by using a defined sequencing for the element (e.g. static variable or process local variable) and read the result form this variable.  In case the output is connected more than once the delay time is running too fast since the timer will be incremented each function call. If the element is only conditionally calculated or directly connected to a OR or AND, it might happen that the delay element is not calculated. In that case internal time value gets not updated and the delay runs longer than defined by the delay time. |
